# Qwen3.8 reconstruction continuation design

State slice: `interpretability-lab-sandbox-v1`.

The v3 and v4 Qwen3.8 internal qualifications both reached the model logits
through the fixed layer-32 decoder hook, but both failed the same maximum
per-row reconstruction gate.  The observed NMSE values were `0.2530649294`
for the published `v2/sae_L32_final.pt` asset and `0.2636105840` for the
published `stage1/sae_L32_final.pt` asset.  Those packets are terminal
historical evidence.  This document does not reopen them and contains no
model, corpus, activation, or result bytes.

The fresh continuation uses the otherwise unused layer-33 model-matched asset
(`v2/sae_L33_final.pt`) from the pinned upstream revision.  The layer-33 design
is recorded in
`configs/qwen3.8-27b-reconstruction-v5-layer33-design-only.json`; the compiler
binds its canonical path and the runner derives the layer from the packet.

The next valid hypothesis is compatibility, not threshold repair: a
code-domain SAE may not represent the fresh corpus distribution, and the
asset's training hook may be the layer input rather than the layer output.
The base design predeclares two layer-32 capture candidates in a fixed order;
the fresh continuation moves the pair to layer 33 and binds the unused
model-matched asset.  The candidate hook is selected on fit data, locked before
tune, and never selected from assessment results.  The existing
decoder-output adapter remains unchanged for the closed packets.

The reconstruction estimand is pooled FVU with one global target mean,
reported with maximum row NMSE.  This prevents a large row from hiding a
localized collapse while avoiding the per-row denominator as the primary
metric.  The design freezes pooled FVU limits of `0.20` for fit, tune, and
assessment and an assessment maximum row NMSE of `0.40`; these values are
protocol inputs for a new packet, not retroactive changes to v3 or v4.

The feature asset must use input width `5120`, feature width `40960`, Top-K
`50`, unit-norm decoder rows, and the stored `sqrt(d)/mean-norm` scale.  A
future training runner must capture every non-padding token, keep raw
activations below a fresh owner-only custody root, and emit aggregate metrics
only.  It must bind the model tree, runtime/device attestation, fresh corpus,
asset digest, and local authorization before loading the model.  No network
access is allowed during model execution.

Qualification remains sequential: custody and runtime, native/instrumented
parity, deterministic repeatability, exact no-op, intervention reach,
reconstruction, feature stability, scrubbing reach, and independent aggregate
recomputation.  Held-out causal effects require a separately frozen packet and
the required independent packet-bound acceptance.  Continual-learning
comparisons remain closed until those causal gates pass.

The machine-readable base boundary is
[`configs/qwen3.8-27b-reconstruction-v5-design-only.json`](../configs/qwen3.8-27b-reconstruction-v5-design-only.json).
It is design-only: null custody and asset digests intentionally prevent
execution.  The diagnostic implementation is
[`src/interp_lab/reconstruction.py`](../src/interp_lab/reconstruction.py).

Once the owner-only inputs exist, the design can be materialized with
[`scripts/freeze_qwen38_reconstruction_v5.py`](../scripts/freeze_qwen38_reconstruction_v5.py).
The compiler writes a new `interp-lab.assessment-packet.v1` packet, binds the
model tree, feature file, and corpus hashes, pins the Transformers version and
source revision supplied by the operator, and sets the packet-bound internal
execution fields.  It refuses changed design bytes, non-owner-only custody,
outside-root paths, symlinks, missing runtime revisions, and altered hook or
feature contracts.  It never loads the model or creates an authorization.

The execution entrypoint is
[`scripts/run_real_qwen38_reconstruction_v5.py`](../scripts/run_real_qwen38_reconstruction_v5.py).
It supports the packet's internal gate, captures all nonpadding tokens in
batches, moves SAE matrices to the attested CUDA device, selects the hook on
fit data, and writes only aggregate qualification output below the custody
root.  It accepts either a separate execution binding containing
`packet.digest` or the custody-bound packet itself; both forms are checked
against the exact packet digest.

The fresh prompt roster is generated by
[`scripts/generate_qwen38_reconstruction_v5_corpus.py`](../scripts/generate_qwen38_reconstruction_v5_corpus.py)
inside the custody root.  It is deterministic, document- and family-disjoint,
and contains no model-derived bytes.

The layer-33 V5 packet was not executed.  Its H100 configuration canary
failed before model loading because Transformers 4.57.3 does not register the
checkpoint's `qwen3_5` architecture.  That failure is retained as a closed
runtime qualification record; changing the runtime inside the V5 packet would
invalidate its identity.

V6 is a fresh continuation with the same model, layer-33 asset, corpus
contract, and reconstruction thresholds, but a pinned Transformers main
source revision that passed the architecture and class import canaries:
`5.18.0.dev0` at
`dbea10932a0e18f40d8103a3bae6fa7927f8d36e`.  Its design-only boundary is
[`configs/qwen3.8-27b-reconstruction-v6-transformers-main-design-only.json`](../configs/qwen3.8-27b-reconstruction-v6-transformers-main-design-only.json).
The V5 preparation entrypoint accepts the V6 design and explicit runtime
tokens, so the V6 packet remains separately digest-bound.  No V5 corpus,
packet, activation, or result bytes are V6 inputs.

The V6 processor attempt also showed that this multimodal checkpoint needs
Pillow and Torchvision at load time.  That attempt stopped before model
construction.  V7 is the next fresh runtime continuation, pinning
Torchvision `0.21.0` (the Torch `2.6.0` compatible release) and Pillow
`11.3.0` in addition to the V6 Transformers source.  Its boundary is
[`configs/qwen3.8-27b-reconstruction-v7-vision-runtime-design-only.json`](../configs/qwen3.8-27b-reconstruction-v7-vision-runtime-design-only.json).

For a Gman batch job, run
[`scripts/prepare_and_run_qwen38_reconstruction_v5.py`](../scripts/prepare_and_run_qwen38_reconstruction_v5.py)
after acquisition.  It compiles the packet and internal authorization,
attests the runtime, writes the custody manifest, switches the process to
offline mode, and invokes the qualification runner.
